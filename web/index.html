测评说明

Noctua 目前聚焦于文本类 LLM 推理协议，在已接入协议下评测流式输出、工具调用与视觉输入三类能力。已支持的文本协议：OpenAI Chat Completions API、Anthropic Messages API；OpenAI Responses API 暂未纳入。

协议矩阵

支持的协议类型

服务商清单里常见三种 LLM 推理协议。Noctua 目前仅对前两种提供用例库、真实请求跑批与报告导出；OpenAI Responses API 尚未纳入评测范围。

协议 典型 Endpoint 评测状态
OpenAI Chat Completions API POST /v1/chat/completions 已支持
Anthropic Messages API POST /v1/messages 已支持
OpenAI Responses API POST /v1/responses 暂未支持

概览

什么是协议兼容性测评

配置目标渠道的 API Key、Base URL、Model，从结构化用例库中选择测试集，由后端发起真实 HTTP 请求。每个 case 会输出参数是否被支持、断言是否通过、与 baseline 的结构差异，以及面向网关的处置建议。

使用流程

推荐使用流程

  1. 打开渠道参数测评工具，按页面上的五步向导选好测评模型、协议、Baseline（对照基准）与要测评的渠道——完成后即可准备跑测。
  2. 填写各渠道的连接信息（Endpoint 接口地址、API Key 访问密钥、API 模型 ID），勾选要验证的 case，点击「运行测试」——工具会向各渠道发出真实请求。
  3. 等待跑批完成——每个 case 会直接给出「是否达标」结论，以及与 Baseline 的响应差异明细，无需自行判读原始数据。
  4. 打开渠道参数测评报告查看本次报告——包含各渠道接入建议排序与术语说明，可直接用于结论汇报。

测评产出

测评产出

  • 参数/请求是否被供应商支持、拒绝、静默接受但未证明生效
  • 响应是否满足断言（HTTP 状态、必填字段、usage、thinking 证据等）
  • 与 baseline 响应的 JSON 结构差异（字段存在性与类型）
  • 面向网关的处置建议（放行、过滤、适配等）

已支持测评渠道

梳理各 API 平台已接入的文本协议（渠道名称旁标签），以及各测评模型在渠道上的协议覆盖（展开表格）。

已支持测评协议

在同一协议下横向对比各渠道官方 API 文档中的参数覆盖与扩展差异；矩阵数据来自 docs/*.md（2026-06-25 对照官方文档更新）。

已支持测评模型

按测评模型查询其在各渠道的 API 模型 ID 与模型级协议支持（与「已支持测评渠道」中的渠道级协议标签相互独立）。支持模糊匹配：大小写、连字符与空格等差异。

        映射说明

        LLM 网关对外通常暴露 OpenAI-compatible 错误形态；各上游渠道的错误字段、码值与 HTTP 语义并不一致。本模块整理渠道原生错误与建议的 OpenAI error 映射，供网关适配与排障参考。

        渠道错误码

        按渠道浏览错误响应 envelope 与代表性错误码条目；完整文档见 docs/errorcode/。

        错误码映射

        按统一场景横向对比各渠道原生错误与建议的 OpenAI error 映射；点击单元格查看详情。
